# Goal

## Original request and sources

Record the supplied goal faithfully, its specification paths/links, the target project(s), and relevant user clarifications. Separate intended requirements from current behavior.

The Documentation/scribe preserves the original request/source evidence and lead-approved criteria. Label verified source facts separately from unresolved assumptions.

## Scope and deliverables

Record required workflows, integration boundaries, artifacts, and explicit exclusions.

## Constraints and assumptions

Record applicable repository guidance, stack, dependency/permission constraints, routine decisions, and any assumption that affects acceptance.

## Acceptance criteria

| ID | Observable requirement | Verification method |
| --- | --- | --- |
| AC-001 | Replace with required behavior observable by a user or caller. | Identify the command, behavioral check, or inspection and expected outcome. |
| AC-002 | Relevant docs accurately describe the delivered structure, behavior, and setup. | Check affected docs, important commands/examples, paths, and links against the implementation. |

## Documentation and discrepancies

Link relevant docs and record material doc/code conflicts, evidence, resolution or required answer, and affected criteria. Keep unresolved consequential conflicts visible.

## Authorized scope changes

Record user-authorized changes with date, reason, and affected original criteria; do not silently weaken acceptance.
